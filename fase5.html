Pixel Detective Edge

🎯 Ini yang Membedakanmu

Pentester biasa menggunakan tools yang sudah ada. Pixel Detective memahami tools, memodifikasinya, dan membuat tools sendiri ketika yang ada tidak cukup. Inilah "edge" yang membuatmu bernilai lebih.

Prinsip: Jangan hanya konsumen tools. Jadilah pencipta. Setiap tool yang kamu buat adalah "pixel" yang kamu kuasai sepenuhnya.

⚙️ 5.1 Recon Automation — Pipeline Sendiri

Bangun pipeline recon yang bisa dijalankan dengan satu perintah.

Step-by-Step:

  1. Desain alur — subdomain → probe → screenshot → dir bust → vuln scan → diff monitoring.
  2. Pilih tools — subfinder, httpx, gowitness, ffuf, nuclei (projectdiscovery ecosystem).
  3. Struktur output — folder per target, file per step, timestamp.
  4. Error handling — cek dependency, timeout, retry.
  5. Notifikasi — kirim hasil ke Discord/Telegram via webhook.
  6. Diff monitoring — bandingkan hasil hari ini vs kemarin, alert jika ada perubahan.

💡 Contoh Kompleks: Recon Pipeline + Discord Notification

#!/bin/bash
# pixel-recon-advanced.sh — Recon pipeline dengan notifikasi Discord
# Usage: ./pixel-recon-advanced.sh target.com 

DOMAIN="${1:?Usage: $0  }"
WEBHOOK="${2:-}"
OUT="recon-${DOMAIN}-$(date +%Y%m%d-%H%M%S)"
PREV_OUT=$(ls -d recon-${DOMAIN}-* 2>/dev/null | tail -2 | head -1)

mkdir -p "$OUT"/{subs,live,dirs,js,screenshots,vulns}

log() { echo "[$(date +%H:%M:%S)] $*"; }

# ── Dependency check ──
for tool in subfinder httpx ffuf nuclei gowitness jq; do
  command -v "$tool" &>/dev/null || { echo "[!] Missing: $tool"; exit 1; }
done

# ── Step 1: Subdomain ──
log "Subdomain enumeration..."
subfinder -d "$DOMAIN" -all -silent -o "$OUT/subs/subfinder.txt"
curl -s "https://crt.sh/?q=%25.$DOMAIN&output=json" \
  | jq -r '.[].name_value' 2>/dev/null \
  | sed 's/\*\.//g' | sort -u > "$OUT/subs/crtsh.txt"
cat "$OUT"/subs/*.txt | sort -u > "$OUT/subs/all.txt"
SUBS_COUNT=$(wc -l < "$OUT/subs/all.txt")
log "→ $SUBS_COUNT subdomain unik"

# ── Step 2: Live hosts ──
log "Probing live hosts..."
cat "$OUT/subs/all.txt" | httpx -silent -mc 200,301,302,403 \
  -o "$OUT/live/live.txt"
LIVE_COUNT=$(wc -l < "$OUT/live/live.txt")
log "→ $LIVE_COUNT host hidup"

# ── Step 3: Screenshot ──
log "Screenshot hosts..."
gowitness scan file -f "$OUT/live/live.txt" \
  --screenshot-path "$OUT/screenshots/" --write-db 2>/dev/null

# ── Step 4: Dir busting (parallel, background) ──
log "Directory busting..."
while IFS= read -r url; do
  hostname=$(echo "$url" | sed 's|https\?://||; s|/.*||')
  ffuf -u "${url}/FUZZ" \
    -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
    -mc 200,301,302,403 -t 50 -s \
    -o "$OUT/dirs/${hostname}.json" -of json 2>/dev/null &
done < "$OUT/live/live.txt"
wait
log "→ Directory scan selesai"

# ── Step 5: JS endpoint extraction ──
log "Ekstraksi endpoint JS..."
while IFS= read -r url; do
  curl -s "$url" \
    | grep -oE 'src="[^"]+\.js[^"]*"' \
    | sed 's/src="//; s/"$//' \
    | while IFS= read -r js; do
        [[ "$js" != http* ]] && js=$(echo "$url" | sed 's|\(https\?://[^/]*\).*|\1|')/"$js"
        curl -s "$js" | grep -oE '["'\''](/api/[a-zA-Z0-9_/.-]+)["'\'']' \
          | tr -d '"'\'''
      done
done < "$OUT/live/live.txt" | sort -u > "$OUT/js/endpoints.txt"
log "→ $(wc -l < "$OUT/js/endpoints.txt") endpoint ditemukan"

# ── Step 6: Nuclei scan ──
log "Vulnerability scan..."
nuclei -l "$OUT/live/live.txt" -severity low,medium,high,critical \
  -o "$OUT/vulns/nuclei.txt" -silent 2>/dev/null
VULN_COUNT=$(wc -l < "$OUT/vulns/nuclei.txt" 2>/dev/null || echo 0)
log "→ $VULN_COUNT potensi vuln"

# ── Step 7: Diff monitoring ──
DIFF_MSG=""
if [[ -n "$PREV_OUT" && -d "$PREV_OUT" ]]; then
  NEW_SUBS=$(comm -13 <(sort "$PREV_OUT/subs/all.txt") <(sort "$OUT/subs/all.txt") | wc -l)
  [[ "$NEW_SUBS" -gt 0 ]] && DIFF_MSG="🆕 $NEW_SUBS subdomain baru!"
fi

# ── Step 8: Discord notification ──
if [[ -n "$WEBHOOK" ]]; then
  PAYLOAD=$(cat < /dev/null
  log "→ Notifikasi Discord terkirim"
fi

log "✓ Selesai. Hasil: $OUT"

Penjelasan: Pipeline ini menambahkan:
• Dependency check — gagal cepat jika tool tidak ada
• Parallel dir busting — & + wait
• Diff monitoring — bandingkan dengan recon sebelumnya
• Discord notification — hasil ringkas via webhook

🔧 5.2 Custom Tooling — Buat Sendiri

Ketika tools yang ada tidak cukup, buat sendiri. Ini skill yang paling dihargai.

Step-by-Step:

  1. Identifikasi gap — apa yang tidak bisa dilakukan tool yang ada?
  2. Desain — input, output, edge case, error handling.
  3. Implementasi — mulai sederhana, iterasi.
  4. Testing — uji di lab legal, pastikan tidak false positive.
  5. Dokumentasi — README, usage, contoh.
  6. Publikasi — GitHub dengan lisensi (MIT/GPL).

💡 Contoh Kompleks: Tool — JavaScript Secret Scanner

#!/usr/bin/env python3
"""
js-secret-hunter.py — Cari secret/API key di file JavaScript
Usage: python3 js-secret-hunter.py 
"""

import re
import sys
import requests

# Pattern untuk secret umum
PATTERNS = {
    "AWS Access Key": r"AKIA[0-9A-Z]{16}",
    "AWS Secret Key": r"aws_secret_access_key['\"]?\s*[:=]\s*['\"]?([A-Za-z0-9/+=]{40})",
    "Google API Key": r"AIza[0-9A-Za-z\-_]{35}",
    "GitHub Token": r"gh[pousr]_[A-Za-z0-9_]{36,255}",
    "Slack Token": r"xox[baprs]-[0-9A-Za-z\-]{10,}",
    "Stripe Key": r"sk_live_[0-9a-zA-Z]{24}",
    "JWT": r"eyJ[A-Za-z0-9_-]+\.eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+",
    "Generic API Key": r"(?i)(api[_-]?key|apikey)['\"]?\s*[:=]\s*['\"]([A-Za-z0-9_\-]{16,})['\"]",
    "Generic Secret": r"(?i)(secret|password|passwd|pwd)['\"]?\s*[:=]\s*['\"]([^'\"]{8,})['\"]",
    "Private Key": r"-----BEGIN (RSA |EC |DSA )?PRIVATE KEY-----",
}

def fetch_content(source):
    """Ambil konten dari URL atau file lokal."""
    if source.startswith(('http://', 'https://')):
        try:
            r = requests.get(source, timeout=10, verify=False)
            return r.text
        except Exception as e:
            print(f"[!] Gagal fetch {source}: {e}")
            return ""
    else:
        try:
            with open(source, 'r', errors='ignore') as f:
                return f.read()
        except Exception as e:
            print(f"[!] Gagal baca {source}: {e}")
            return ""

def scan(content, source):
    """Scan konten untuk secret patterns."""
    findings = []
    for name, pattern in PATTERNS.items():
        for match in re.finditer(pattern, content):
            # Ambil context sekitar match (50 char sebelum/sesudah)
            start = max(0, match.start() - 50)
            end = min(len(content), match.end() + 50)
            context = content[start:end].replace('\n', ' ')

            findings.append({
                "type": name,
                "match": match.group(0)[:100],  # truncate
                "context": context,
                "source": source,
            })
    return findings

def main():
    if len(sys.argv) < 2:
        print("Usage: python3 js-secret-hunter.py ")
        sys.exit(1)

    source = sys.argv[1]
    print(f"[*] Scanning: {source}")

    content = fetch_content(source)
    if not content:
        return

    print(f"[*] Ukuran konten: {len(content)} bytes")
    findings = scan(content, source)

    if not findings:
        print("[✓] Tidak ada secret ditemukan.")
        return

    print(f"\n[!] Ditemukan {len(findings)} potensi secret:\n")
    for i, f in enumerate(findings, 1):
        print(f"  [{i}] {f['type']}")
        print(f"      Match  : {f['match']}")
        print(f"      Context: ...{f['context']}...")
        print()

if __name__ == "__main__":
    main()

Penjelasan: Tool ini:
• Menggunakan regex untuk pattern matching
• Mendukung input URL atau file lokal
• Memberikan context sekitar match (membantu verifikasi false positive)
• Bisa diperluas dengan pattern baru

Etika: Hanya scan file/URL yang kamu punya izin. Jangan scan target orang tanpa izin.

📝 5.3 Writeup — Mendokumentasikan "Pixel"

Writeup yang baik bukan hanya "apa yang saya lakukan", tapi "mengapa".

Struktur Writeup yang Baik:

  1. Judul & Metadata — nama mesin/CTF, OS, difficulty, tanggal.
  2. Summary — 2–3 kalimat tentang apa yang dipelajari.
  3. Recon — nmap, enumeration, temuan awal.
  4. Exploitation — langkah, payload, screenshot, penjelasan kenapa bekerja.
  5. Privilege Escalation — langkah, tool, analisis.
  6. Lessons Learned — apa yang bisa diperbaiki, teknik baru.
  7. References — sumber, CVE, dokumentasi.
Tips: Tulis writeup selama mengerjakan, bukan setelahnya. Catat setiap langkah, termasuk yang gagal — kegagalan adalah pelajaran berharga.
